# Page-representation bake-off (2026-09-24)

**Question.** How should the Jev-driven tester represent a web page? Ranking (owner-decided):
1) pass rate on a hard-stack matrix, 2) no LLM in the run loop, 3) speed, 4) cost.
Rename survival is not a criterion.

**Verdict: ship A+G.** A+ is the in-page snapshot, extended to pierce open shadow roots and same-origin
iframes. G is a goal-anchored keep in `compact()`. Together they pass **120/120** on the
matrix. The baseline passes **35/120**. B (Playwright aria snapshot) with G also passes 120/120.
It loses on rank 3: its snapshot is 2.8x slower, and it needs extra per-field lookups.
No LLM is used anywhere. Cost per run is $0.000119 (baseline: $0.000220, because failing runs burn steps).

Every number below comes from a run in this branch (`v1-bakeoff`). The engine is `jev`
(OpenRouter `typesafe/jev-1.13`), the budget is 30, and n=5 unless stated.

## Setup

**Tier-2 stacks** (`bench/stacks/`, deps pinned exactly, `build.sh` builds all of them, `serve.mjs`
serves them on ports 5101-5108): vanilla HTML (native select) · React 19 + MUI 9 · React + antd 6 ·
React + Radix (shadcn structure) · Vue 3 + Element Plus 2.14 · Web Components (Shoelace 2.20 + Lit 3,
every control in an open shadow root) · same-origin iframe (form and list inside `<iframe>`, success
navigates the top window) · legacy (layout tables, bare `<td>` labels, jQuery 3.7, `<input type=button>`).

**The same 3 tasks on every stack** (`bench/tasks.mjs`):
- T1: log in. Assert `/home?u=` + "Welcome, demo@bench.test".
- T2: fill Project name, choose plan **Enterprise** (last option), accept the terms, submit. Assert `/success?name=Orion&plan=Enterprise` + text.
- T3: from a 60-row customer list, open **Quentin Harlow (row 57)**. Assert `/customers/57` + "Customer detail: Quentin Harlow".

`bench/verify-stacks.mjs` checks all 24 cells with hand-written Playwright and no model. It confirms
each assertion is false on the start page and true after a scripted solve. Result: 24/24. The
scripted solve itself needed library-specific selectors on 3 stacks. antd options are divs, and
Element Plus options are divs. The Shoelace checkbox `<input>` is not actionable, so a human must click the `label` part.

**Approaches** (`bench/approaches/`). All run through `bench/lib/core.mjs`, a parametrised copy of
`runOnce`. `src/` is not edited.

## What each failure was (read from the step paths)

- **A, native select (vanilla, iframe, legacy T2): `SELECT` has no dispatch branch.** The
  select's options also dedupe to the placeholder. Path: `SELECT Choose a plan…` ×13, then MAX_STEPS.
  This was already listed in `fixtures/README.md` and was still open.
- **A, MUI / antd / Element Plus T2: the checkbox is never offered.** The real `<input>` is `opacity:0`
  (MUI, antd) or 0x0 (Element Plus), so `visible()` drops it. Its `<label>` is not in `SEL`.
- **A, Web Components T1/T2/T3: 0 actions.** `querySelectorAll` does not enter shadow roots. The model
  gets only WAIT/DONE/BLOCKED.
- **A, iframe: only the 3 nav links.** The iframe's controls are invisible to it.
- **Everyone without G, T3: the row-57 link is never offered.** At budget 30 the list page has 63
  candidates, and 33 are dropped in document order. Representation is not the cause: A, A+, B and C all drop
  it the same way. G keeps it (rank -1, because every label token is in the goal), and T3 then passes in **1 step** on every
  stack. G changes nothing on a page where nothing is dropped: T1/T2 are 80/80 with and without it.
- **C, antd T2 (0/5): the AX tree has no role for antd's visible option rows** (plain divs). The
  `role=option` nodes are a 0x0 mirror, so clicking them fails (`!stale` ×5). B handles this only through
  Playwright's `cursor=pointer` hint. A+ handles it through the existing popup-row recovery.

## Two findings worth keeping

**1. Removing the chosen option removes the evidence that it was chosen.** A+ with the SELECT fix still failed
vanilla T2. The trace: `SELECT Plan: Enterprise` at 0.99, then **BLOCKED 4/4 at 0.54-0.64**. After
the selection, Enterprise is no longer offered, and nothing in `state.elements` says Plan = Enterprise.
The checkbox showed `v:"on"`, its value attribute, whether checked or not. The fix shows `{r:"combobox", l:"Plan", v:"Enterprise"}` as a
non-choosable element and gives checkboxes `v:"checked"/"unchecked"`. After it: SELECT 1.00, CLICK checkbox 1.00, CLICK Create 0.97,
DONE_VERIFIED in 4 steps. Finding #2 ("remove bad options") has a corollary: when you
remove the option that is already satisfied, you must keep its state visible.

**2. The per-snapshot stamp generation fixes the `ordinal-carryover` fixture for free.** `filled` is
keyed by node id. With `n0..nK`, the same ordinal on the next page suppresses typing (the open defect).
A+ stamps `<gen>nK`, so `filled` never carries over. `ordinal-carryover` goes 0/3 → 3/3, and no
matrix run typed the same field twice.

## Verdict

1. **Ship A+ as `src/snapshot.js`.** It is in-page, one `evaluate()`, and the fastest (1.4 ms median). With G it passes 120/120 on the matrix.
2. **Ship G, the SELECT branch, and the state elements in `loop.mjs`.** G alone turns T3 from 0/40 to 40/40.
3. **Keep B as the documented alternative.** It has the same pass rate. It costs 2.8x in snapshot time, one extra evaluate per textbox, a
   placeholder regex (the tree has no option values), and a password value in plain text in the tree until the type lookup masks it.
4. **Drop C for the run loop.** With lazy mapping it is not 8.6x any more (1.8 ms against 1.6 ms). But it cannot see antd's option rows,
   and it needs an extra `describeNode` per field. Keep it as the offline oracle, as the README already says.
5. **What it costs:** $0.000119 per run on jev, and median wall time of 1,836 ms on passing runs. The snapshot is well under 1% of a
   step. Jev's decision (~350 ms) and the page waits are the rest.

**Limits I measured and did not fix.** `READY` counts light-DOM controls only, so on the Web Components
stack every non-typing step waits the full 4 s: wc T2 takes 18.7 s for 5 steps with every approach. A
deep `READY` is the next cheap win. The same "only the first N" starvation still applies when the goal
does not name the target (table-pagination). `negative-control` (offscreen/opacity decoys) and
`select-innertext` are unchanged.

`snapshot.js` changes (header of `bench/approaches/aplus-snapshot.js`): (1) a TreeWalker deep walk through
`el.shadowRoot` and same-origin `iframe.contentDocument`; (2) `getElementById`/`label[for]` scoped to
`el.getRootNode()`; (3) `getComputedStyle` from the element's own window; (4) one `select` action per
option with a distinct node plus `selectNode/selectLabel/optionLabel`; (5) a hidden checkbox/radio `<input>`
offered once, stamped on its visible `<label>`; (6) a per-snapshot stamp generation; (7) `<input
type=submit|button|reset>` named by its value, and `<select>` never named by its own innerText; (8)
text read through `<slot>` inside shadow roots.

## Prior art (15 min)

- **mapwright** (npm 1.0.0-pre.12): not an explorer. You write Playwright "walk" specs with a
  role-based page-object vocabulary (surface / overlay / menu / listbox), and it records full-page
  screenshots into a browsable report. *Steal:* the screenshot-per-step browsable report for our trace, and its
  role-based POM vocabulary as the target shape for codegen.
- **Stagehand** (v3): CDP `getFullAXTree` per frame (DFS, including OOPIF). Each node gets an EncodedId (frame ordinal + node
  id) and an absolute XPath for acting. *Steal:* frame-ordinal-prefixed ids for cross-origin iframes, the one
  case A+ cannot reach (`contentDocument` is null).
- **browser-use** DOM serializer: CDP DOM + AX + snapshot merged into an "enhanced" DOM. A
  `ClickableElementDetector` includes shadow hosts and iframe documents. Indices come from backendNodeId. Bounding-box
  containment drops nested children of a clickable parent. *Steal:* the containment filter (it would dedupe
  antd's `menuitem` + `link` pairs, which A+ offers twice).
- **Playwright MCP** `browser_snapshot`: the same AI aria snapshot as B (`[ref=eN]`, iframes inlined),
  and it acts by ref. *Steal:* nothing beyond B. It confirms B is the industry default, and this matrix shows it
  gains no pass rate over A+ at 2.8x the snapshot cost.

**Defect 1: the submit hold-back.** `compact()` marks a form pending while any row in it still has
a `SELECT` op. After Enterprise is chosen, Starter/Team/Growth/Business still carry `SELECT`, so Create
project is removed forever. The path: `TYPE_TEXT name | SELECT Enterprise | CLICK terms | DONE!rej ×3 | DONE`.

`node bench/repro/discover-hold-back.mjs` prints `DEFECT: submit withheld` with
`values: {"Project name":"Orion","Plan":"Enterprise"}`. Suggested fix: count a SELECT row as pending only while
its control is unset (`!r.a.current_value`, or when the placeholder is the current value).

**Defect 2: `checkVisibility({opacityProperty:true})` (snapshot.js:31) drops Element Plus's only Plan
control.** The `role=combobox` input sits in `div.el-select__input-wrapper.is-hidden` (opacity 0). The
clickable `.el-select__wrapper` (360x32) has no role. The model sees only Project name and the
checkbox, then answers BLOCKED. Repro: `node bench/repro/discover-ep-combobox.mjs`. Suggested fix: exempt form
controls (`input`, `select`, `[role=combobox]`) from the ancestor-opacity rule when the nearest
`cursor:pointer` ancestor is visible, or offer that ancestor as a proxy, like the hidden-checkbox label.

  spends $0, and looks like success. `bench/run-all.sh` writes there too. It is the historical bake-off, not "measure this tree".

  bake-off approaches in `bench/approaches/`.
- **Ports 5101-5108 must be free.** `serve.mjs` binds them fixed, one per stack.
- **Node `^20.19` or `>=22.12`** (Vite 8). Playwright alone needs `>=20`.
- The Vite "chunks larger than 500 kB" warnings during the build are expected.
- `npx playwright install chromium` was not tested from an empty browser cache (this machine has it cached).
